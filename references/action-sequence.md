# 让观众看懂一个变化

需要拍出速度、重量、装配、交接或其他空间关系变化时，先用一句可以从画面验证的话确定动作。写出开始时的关系、发生变化的瞬间、结束时的关系。抽象词可以保留作美术方向，把它落实为能观察到的东西。

## GT18 的十二秒怎样讲清超车

| 时间 | 在画面里找什么 | 机位为什么放在这里 |
|---|---|---|
| 0–2 秒 | 蓝车先来，橙车在后；路肩和护栏给出运动方向 | 路旁长焦建立两车的顺序，观众先认出追赶对象 |
| 2–5 秒 | 从橙车后方看到蓝车，间距缩小；制动时尾灯变亮 | 低位跟拍让观众站在追赶者一边，又保留前车作距离参照 |
| 5–8 秒 | 橙车切入内线，两车并排、交换顺序 | 弯外机位同时看住两条走线。约 6.7 秒换位，剪辑把这段连续动作留在同一镜 |
| 8–12 秒 | 橙车在前，蓝车在后；龙门架和逐渐拉远的机位交代结果 | 换角度后，仍能凭车色与前后关系认出领先者 |

四镜和时长取自这个案例。给新题材选真正决定观众能否理解的瞬间，再决定是否切镜。若剪辑正好遮住交接、扣合或超越，可让该动作在同一视角里完成，或在下一镜提供足够清楚的连续性线索。

## 把模型、动作和反应接起来

- **为景别做资产。** 赛车工程单独生成车体 GLB 和前后视图，再由影片加载模型。近景看到轮拱包住轮胎、尾翼离开车身，转向轮和刹车灯也能独立驱动。先列出新镜头最近会拍到的轮廓、接缝和活动部件，做相应视角的小样。二维角色交接可先画两只手和道具接触的姿势。
- **为因果选状态。** 赛车用沿赛道的位置与横向偏移确定车位，车轮滚动读取行程，车身俯仰与刹车灯共同读取制动量。把主动作写成可按时间取值的位置、接触或受力状态，挑观众能察觉的一两种反馈与它共用。要声音时，让声音落点也读这个状态，必要时再加材质或距离带来的延迟。
- **为摄影选环境。** 车身保持清楚，重复路肩标记交代速度，湿路局部反光交代材质，轮后水雾交代轮胎与路面接触。调试时逐项开关：关掉某效果后，哪条运动或材质信息变难读？全开反而遮住关键动作，就减弱那一层。
- **迁移到另一题材。** 拍相机镜头旋入机身：先看卡口间隙，再从能同时看见两处标记的角度拍到旋转对齐，最后让手松开并看见镜头仍固定在位。有声版让锁扣声落在扣合帧。二维分解图同样可以用对齐标记讲清这个动作。

## 从实际成片核对

先连续播放关键动作，必要时静音，看能否辨认主体、追踪变化并指出结果。再从成片抽取切点两侧和事件前中后的帧。根据失败的原因回到对应环节：定格认不出物体就修资产；静帧清楚但看不懂关系变化就修走位、视角或剪辑；对齐了仍显得轻飘就复查接触、姿态与声音。

附带的工具使用 Node.js 和 FFmpeg，读取输入视频的第一路画面。以解码后的零基帧号选择画面，输出一份可离线查看的 HTML。以下帧号用于原赛车片的 30 fps 时间轴，新片按自己的动作和帧率选择。输出目录须存在，文件名须为新名称。

```sh
node scripts/review-frames.mjs film.mp4 review.html "59=建立关系" "60=切入跟拍" "174=进入弯心" "200=接近并排" "226=驶出弯心" "240=换角度看结果" "350=收尾"
```
